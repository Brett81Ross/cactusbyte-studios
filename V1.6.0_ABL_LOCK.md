### A. Release Truth Engine
One central `AppReleaseTruth` model reconciles:
- Recorded: CactusByte production registry / release record.
- Detected: safe app/repository version signal when available.
- Deployed: canonical Vercel production deployment metadata when server-side verification credentials are configured.

The public hub shows simple availability. The Owner Health Center may show full Recorded / Detected / Deployed evidence and mismatches.

A staged or detected version must never be presented as live unless deployment evidence verifies it. If deployment verification credentials are absent, the system must report verification as unavailable rather than inventing a green result.

### B. Native Launch Router
- One launch/install authority replaces competing PWA/install flows.
- Web, Android Direct, and later Google Play are distribution choices, not device-specific builds.
- The same Android application binary adapts across phones, tablets, and Fold form factors.
- Native-required messaging is shown only when a capability genuinely requires the Android wrapper.
- No automatic installation, uninstall, migration, or cutover.

Requirements retained in production:

### C.1 Tablet + Multi-Window QA addendum
This remains a QA addendum to C, not a separate product workstream. Automated Chromium + WebKit coverage includes these CSS-pixel viewports:
- iPad Mini: `744×1133` and `1133×744`.
- iPad Air / Pro 11: `834×1194` and `1194×834`.
- iPad Pro 12.9: `1024×1366` and `1366×1024`.
- Galaxy Tab class: `800×1280` and `1280×800`.
- Large Galaxy Tab class: `924×1480` and `1480×924`.
- Tablet split screen: `600×1024` and `800×768`.
- Samsung DeX / desktop-style Android: `1440×900`.

C.1 gates:
- Emulate touch on tablet scenarios rather than testing only desktop pointer behavior.
- Detect iPad desktop-style/Mac user agents using touch capability (`maxTouchPoints > 1`) so an iPad is not offered Android-only download controls.
- Keep large tablet/DeX content bounded to the existing approximately 1180px shell and no more than four app-card columns.
- Preserve 48px touch targets, no horizontal overflow, contained artwork, and contained Native Launch dialogs across the expanded matrix.
- Narrow split-screen widths may collapse to phone-style single-column layout; full-size portrait tablets must not be forced into phone mode merely because they use a coarse touch pointer.
- Physical iPad hardware remains useful follow-up validation but is not a release blocker after the automated WebKit/Chromium gate passed.

### D. Owner Health Center
Existing CactusByte ID owner authority only. No separate password.

Owner-only evidence may include:
- Canonical app/domain/version truth.
- Production deployment health.
- Registry/source sync health.
- API/data-source health.
- Stripe/entitlement/webhook health where available.
- GitHub Actions release/QA status.

Public users must not receive internal release/debug detail or privileged health data. The production owner-health endpoint fails closed for unauthenticated requests.

### E. Android Migration Center
Locked migration state machine:
1. `LEGACY`
2. `BACKUP_READY`
3. `RESTORE_VERIFIED`
4. `CUTOVER_READY`
5. `PERMANENT`
6. `PLAY_READY`

Rules:
- `CUTOVER_READY` is readiness only; it is not authorization.
- Permanent-signing cutover is separate from v1.6.0.
- Each app cutover requires explicit owner approval.
- Never instruct a user to uninstall a legacy/debug-signed app until backup + restore gates for that app are proven.
- Permanent keys being staged is evidence of signing readiness only; it does not advance any app beyond its migration evidence.
- The v1.6 Migration Center is diagnostic/read-only and contains no uninstall, cutover, or Play-publication action.

## AppReleaseTruth schema

```ts
export type AndroidMigrationState =
  | "LEGACY"
  | "BACKUP_READY"
  | "RESTORE_VERIFIED"
  | "CUTOVER_READY"
  | "PERMANENT"
  | "PLAY_READY";

export type ReleaseEvidence = {
  version: string | null;
  source: string;
  checkedAt: string | null;
  deploymentId?: string | null;
  gitSha?: string | null;
};

export type AppReleaseTruth = {
  appId: string;
  recorded: ReleaseEvidence;
  detected: ReleaseEvidence | null;
  deployed: ReleaseEvidence | null;
  liveVersion: string;
  state: "LIVE" | "MISMATCH" | "STAGED" | "UNVERIFIED";
  androidMigration: AndroidMigrationState;
  androidDirectUrl?: string | null;
  playUrl?: string | null;
  iosUrl?: string | null;
  issues: string[];
  checkedAt: string;
};
```
